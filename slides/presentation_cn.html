1什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）= 检索 + 生成。

大模型知识受限于训练数据、且容易幻觉。RAG 的思路：回答前先从外部语料检索相关资料，塞进提示词，再让大模型基于资料生成答案。

🔑 关键：检索器能否把「回答这个问题真正需要的资料」都找回来。
这正是传统 RAG 与 GraphRAG 的分水岭。

检索 → 生成 的基本回路

2传统 RAG 的实现原理

用向量相似度做检索：把文字变成向量，比谁更接近。

五个步骤

  • ① 切块 语料切成文本块 chunk
  • ② 向量化 每块编码成一个向量
  • ③ 建库 存入向量库（Faiss）
  • ④ 检索 问题也向量化，找最相似 top-k
  • ⑤ 生成 拼上下文交给大模型

核心特征：扁平的相似度匹配 —— 块与块之间没有关联结构。

3传统 RAG 的结构性局限

一个多跳问题

「我最喜欢的那部电影，它的导演是哪里人？」

要答对，得先找「导演是谁」，再找「导演出生在哪」——两个事实往往写在不同资料里：

四个结构性问题

  • 多跳会断链：第 2、3 跳往往不含问题关键词 → 漏召回
  • 块间无关联结构：无法「顺着某个关系往下找」
  • 无法聚合/遍历：「一类邻居 + 过滤」没有对应机制
  • 可解释性弱、易幻觉：上下文残缺时模型倾向「补全」

⚠️ 这不是调参问题。调大 top-k 只会引入更多噪声，后续跳依然不相似 —— 这是扁平相似度检索的结构性缺陷。

4GraphRAG 的实现原理

把「扁平的块集合」换成 实体-关系图：检索 = 在图上按关系走路径。

四个步骤

  • ① 抽取 LLM 抽三元组（主体,关系,客体）
  • ② 建图 三元组连成有向图（记录来源）
  • ③ 遍历 从问题实体沿边多跳走，收集整条链
  • ④ 生成 把路径作为上下文交给大模型

核心区别：后续跳即使字面不相似，也能通过边被精确找到。

5GraphRAG 的优势与能解决的问题

优势能解决什么问题传统 RAG 为何做不到
多跳推理「A 的 B 的 C 是什么」需串联多个事实后续跳与原问题不相似，被漏召回
跨文档串联线索散落在多篇文档、需要拼起来相似度按块独立打分，不懂块间关联
聚合查询「所有子公司 CEO 里谁满足某条件」需遍历+过滤无「遍历一类邻居」机制，只能盲猜 top-k
可解释性需要给出「答案是怎么推出来的」只能给召回块，说不清推理链
抗幻觉减少凭空编造上下文残缺时模型倾向「补全」→ 幻觉

其中 多跳推理 与 聚合查询 是质变能力 —— 不是「效果好一点」，而是「一个能做、一个根本做不到」。

6语料库设计：5 篇文档切成 19 个 chunk

按空行切段落、跳过纯标题块，一个段落 = 一个 chunk（见 common/corpus.py）。每篇的 #1/#6/#8/#12/#16 都是一句隔离声明，正文刻意不出现下一跳关键词。

companies.md（5 块） #1 本篇仅描述星环科技集团的股权与子公司结构，不涉及任何高管人事信息。 #2 星环科技是一家综合性科技集团，横跨 AI、数据平台与网络通信，以控股方式管理旗下多家子公司。 #3 云枢智能是星环科技的全资子公司，专注企业级 AI 推理平台。 #4 恒星数据是星环科技旗下的子公司，主营大规模数据仓库与实时分析引擎。 #5 光年网络同样隶属于星环科技，布局网络通信与边缘计算。 investors.md（2 块） #6 本篇仅记录投资方与被投公司之间的投资关系。 #7 磐石资本是专注科技领域的投资机构，曾投资星环科技，成为其重要股东之一。
leadership.md（4 块） #8 本篇仅记录各公司的 CEO 任职关系，不涉及教育背景或毕业院校。 #9 李明现任云枢智能的 CEO，全面负责产品与经营。 #10 王芳担任恒星数据的 CEO，主导数据平台战略。 #11 陈伟是光年网络的 CEO，负责网络通信业务的整体运营。 people.md（4 块） #12 本篇仅记录人物与其毕业院校，不涉及院校城市，也不涉及任职公司。 #13 李明毕业于未名理工大学，主修计算机科学。 ← 不含「云枢智能」 #14 王芳毕业于明德大学，拥有信息工程学位。 #15 陈伟毕业于北山大学，专业方向为通信工程。 universities.md（4 块） #16 本篇仅记录高校与其所在城市，不涉及任何人物或公司。 #17 未名理工大学坐落于江城，以工科见长。 ← 无「云枢」「李明」 #18 明德大学位于松岛，以信息学科闻名。 #19 北山大学地处云港，在通信与电子领域实力雄厚。

串联 #9→#13→#17 时：#13 不含「云枢智能」、#17 两个关键词都没有 → 传统 RAG 只能捞到 #9，后两块必然漏召回 —— 结构性局限的可复现体现。

6贯穿式对比案例（同语料 · 同问题）

用同一份语料、同一批问题跑两个程序，可用 compare.py 并排对比。

Q1 · 线性多跳

云枢智能的 CEO 毕业于哪所大学？那所大学在哪个城市？

传统 RAGGraphRAG
检索方式相似度 top-k图上多跳遍历
拿到的信息只有「李明是CEO」完整链：云枢→李明→未名理工→江城
答案❌ 无法确定✅ 未名理工大学，江城

Q2 · 聚合多跳

星环科技旗下所有子公司的 CEO 里，谁的母校在江城？

传统 RAGGraphRAG
需要的操作遍历 3 家子公司 + 各查母校 + 按城市过滤图上逐层展开 + 过滤
结果❌ 无法确定✅ 李明（未名理工在江城）

聚合题对传统 RAG 更是彻底无能：它没有「遍历一类邻居」的能力。

6传统 RAG 详细步骤（以 Q1 实跑）

Q1：云枢智能的 CEO 毕业于哪所大学？那所大学在哪个城市？ ① 问题向量化 问题编码成一个 query 向量 ② 相似度检索 在 19 个 chunk 中取 top-3： 1. (score=0.513, leadership.md) 李明现任云枢智能的 CEO… ← 命中第1跳 2. (score=0.469, companies.md) 云枢智能是星环科技的全资子公司… 3. (score=0.422, universities.md) 北山大学地处云港… ← 无关噪声 ③ 拼接上下文 把 top-3 拼成 prompt ④ 交给大模型生成 [生成] 答案： 根据现有资料无法确定。上下文仅提到李明是云枢智能的 CEO，但未说明李明的毕业院校。

这一趟命中了什么

  • ✓ #9 含「云枢智能」→ 相似 → 召回
  • ✗ #13「李明毕业于未名理工」不含「云枢智能」 → 漏
  • ✗ #17「未名理工位于江城」两个关键词都没有 → 更漏

top-3 里甚至混入了完全无关的 #19（北山大学），这就是噪声。

拿到的上下文只覆盖了第 1 跳，第 2、3 跳的事实压根没进 prompt。

6为什么会失败：断链分析

问题：云枢智能的 CEO 毕业于哪？在哪个城市？

三个根因

  • 只有第 1 跳与问题相似：问题含「云枢智能 / CEO」，仅 #9 命中
  • 第 2、3 跳天然不相似：#13/#17 不含问题关键词，向量距离远 → 漏召回
  • 调大 top-k 无解：只会引入更多噪声（如 #19），后续跳依然不相似

⚠️ 上下文残缺 → 大模型要么答不出，要么「补全」缺失信息 → 幻觉。

这是扁平相似度检索的结构性缺陷 —— 不是调参能解决的。

7GraphRAG 详细步骤 · 第一步：抽取

LLM 把每篇文档变成 三元组（主体 — 关系 → 客体），并记录来源文档。

星环科技 --HAS_SUBSIDIARY--> 云枢智能 [companies.md] 星环科技 --HAS_SUBSIDIARY--> 恒星数据 [companies.md] 星环科技 --HAS_SUBSIDIARY--> 光年网络 [companies.md] 磐石资本 --INVESTED_IN--> 星环科技 [investors.md] 云枢智能 --HAS_CEO--> 李明 [leadership.md] 恒星数据 --HAS_CEO--> 王芳 [leadership.md] 光年网络 --HAS_CEO--> 陈伟 [leadership.md] 李明 --GRADUATED_FROM--> 未名理工大学 [people.md] 王芳 --GRADUATED_FROM--> 明德大学 [people.md] 陈伟 --GRADUATED_FROM--> 北山大学 [people.md] 未名理工大学 --LOCATED_IN--> 江城 [universities.md] 明德大学 --LOCATED_IN--> 松岛 [universities.md] 北山大学 --LOCATED_IN--> 云港 [universities.md] —— 共 13 条

固定关系集（教学版）

  • HAS_SUBSIDIARY 母公司 → 子公司
  • HAS_CEO 公司 → CEO
  • GRADUATED_FROM 人 → 高校
  • LOCATED_IN 高校 → 城市
  • INVESTED_IN 投资方 → 公司

三步中间结果全部打印，便于现场观察它是怎么走通那条链的。

7GraphRAG 详细步骤 · 第二步：建图

三元组连成有向图：节点=实体，边=关系（带来源）。14 个节点，13 条边。

高亮蓝色路径即 Q1 要走的那条链；灰色是图里的其他分支

7GraphRAG 详细步骤 · 第三步：多跳遍历（Q1）

从「云枢智能」出发，沿边走

[GraphRAG] ③ 从起点实体 ['云枢智能'] 开始多跳遍历： 第1跳: 云枢智能 --HAS_CEO--> 李明 第2跳: 李明 --GRADUATED_FROM--> 未名理工大学 第3跳: 未名理工大学 --LOCATED_IN--> 江城 [生成] 答案： 云枢智能的CEO是李明，李明毕业于未名理工大学， 未名理工大学位于江城。

整条链沿边精确走通 —— 不依赖相似度

7对比 · Q2 聚合遍历（展开成树 + 过滤）

Q2：星环科技旗下所有子公司的 CEO 里，谁的母校在江城？

第1跳: 星环科技 --HAS_SUBSIDIARY--> 云枢智能 / 恒星数据 / 光年网络 第2跳: 云枢智能→李明 恒星数据→王芳 光年网络→陈伟 第3跳: 李明→未名理工 王芳→明德大学 陈伟→北山大学 第4跳: 未名理工→江城 明德大学→松岛 北山大学→云港 ⇒ 过滤「城市 = 江城」 ⇒ 李明 ✓

本质：传统 RAG 漏掉的第 2、3 跳，在 GraphRAG 里是图上明确的边。遍历沿边走，不依赖「相不相似」，所以链条不会断 —— 这就是它做到多跳的根本原因。

遍历 + 按城市过滤 ⇒ 李明

8适用边界与取舍

GraphRAG 不是银弹，也有代价。

维度传统 RAGGraphRAG
建库成本低（只需 embedding）高（需 LLM 抽取三元组）
擅长问题单跳、事实查找、语义检索多跳、聚合、关系推理
依赖embedding 质量抽取质量 + 关系设计
可解释性弱强（有显式路径）

💡 实践建议：两者常结合使用 —— 向量检索做粗召回，图结构做关系推理。本 Demo 为突出对比而分开实现。

TAKEAWAYS

一句话记住

传统 RAG 的检索是扁平的相似度匹配，跨文档多跳会断链；
GraphRAG 把线索显式建成实体-关系图，检索变成图上按边走路径，
所以能做到多跳推理与聚合查询 —— 而且每一步可见、可解释。
