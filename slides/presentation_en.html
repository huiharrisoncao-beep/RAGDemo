1What is RAG

RAG (Retrieval-Augmented Generation) = Retrieval + Generation.

An LLM's knowledge is bounded by its training data and prone to hallucination. RAG's idea: before answering, retrieve relevant material from an external corpus, put it into the prompt, then let the LLM generate an answer grounded in that material.

🔑 The crux: can the retriever fetch all the material actually needed to answer? This is exactly where traditional RAG and GraphRAG diverge.

The basic retrieve → generate loop

2How Traditional RAG Works

Retrieval by vector similarity: turn text into vectors, compare who is closest.

Five steps

  • ① Chunk split corpus into blocks
  • ② Embed encode each block to a vector
  • ③ Index store in a vector DB (Faiss)
  • ④ Retrieve find most-similar top-k blocks
  • ⑤ Generate stitch context, call the LLM

Key trait: flat similarity matching — blocks have no relational structure between them.

3The Structural Limitation of Traditional RAG

A multi-hop question

"From which university did the CEO of Yunshu Intelligence graduate, and in which city is that university?"

Answering it chains 3 facts — scattered across different documents:

Why the chain breaks

The question vector only recalls blocks similar to the whole question:

  • ✓ "Yunshu CEO" block → similar → recalled
  • ✗ "Li Ming graduated from Weiming" has no "Yunshu" → not similar → missed
  • ✗ "Weiming is in Jiangcheng" has neither keyword → missed too

⚠️ This is NOT a tuning problem. Later hops are inherently dissimilar to the question; raising top-k only adds noise — a structural flaw of flat similarity retrieval.

3Real Demo Output: Traditional RAG Fails

Retrieved (top-3)

[retrieve] top-3 blocks: 1. (score=0.51, src=leadership.md) Li Ming is the CEO of Yunshu... <- only hop 1 2. (score=0.47, src=companies.md) Yunshu is a subsidiary of Xinghuan... 3. (score=0.42, src=universities.md) Beishan Univ. is in Yungang... <- irrelevant (noise)

The people.md hop and the correct universities hop are never recalled.

Generated answer

[generate] Answer: Cannot be determined from the given material. The context only states Li Ming is the CEO of Yunshu, but not the university he attended.

4How GraphRAG Works

Replace the "flat block set" with an entity-relation graph: retrieval = walking paths along edges.

Four steps

  • ① Extract LLM extracts triples (subj, rel, obj)
  • ② Build triples → a directed graph
  • ③ Traverse walk edges multi-hop from the entity
  • ④ Generate hand the path to the LLM

Key difference: later hops are found precisely via edges, even when textually dissimilar.

5Advantages & Problems Solved

AdvantageProblem it solvesWhy traditional RAG can't
Multi-hop reasoning"C of B of A" — chaining multiple factsLater hops dissimilar to the question, missed
Cross-doc linkingClues scattered across many documentsSimilarity scores each block independently
Aggregate queries"Among all subsidiaries' CEOs, who meets X" — traverse + filterNo "traverse a class of neighbors" mechanism
ExplainabilityShow "how the answer was derived"Can only return blocks, not a reasoning chain
Anti-hallucinationReduce fabricationWith partial context the model tends to "fill in"

Multi-hop reasoning and aggregate queries are the qualitative leap — not "a bit better", but "one can, the other simply cannot".

6End-to-End Comparison (same corpus · same questions)

The corpus is deliberately designed: adjacent hops live in different docs, each doc omits the next hop's keyword → traditional RAG fails reproducibly.

Traditional RAGGraphRAG
Operation neededtraverse 3 subs + look up each alma mater + filter by cityexpand layer-by-layer + filter

Aggregation is even more hopeless for traditional RAG: it has no "traverse a class of neighbors" ability.

7How · Step 1: Extraction

The LLM turns each document into triples (subject — relation → object), keeping the source doc.

Yunshu Intelligence --HAS_CEO--> Li Ming [leadership.md] Li Ming --GRADUATED_FROM--> Weiming Inst. [people.md] Weiming Inst. --LOCATED_IN--> Jiangcheng [universities.md] Xinghuan --HAS_SUBSIDIARY--> Yunshu Intelligence [companies.md] ... 13 triples total

Fixed relation set (teaching version)

  • HAS_SUBSIDIARY parent → subsidiary
  • HAS_CEO company → CEO
  • GRADUATED_FROM person → university
  • LOCATED_IN university → city
  • INVESTED_IN investor → company

A fixed relation set keeps extraction stable and the graph clean; results are cached as graph.json for human review.

7How · Step 2: Build the Graph

Triples form a directed graph: nodes=entities, edges=relations (with source). 14 nodes, 13 edges.

The highlighted blue path is the chain Q1 walks; gray edges are the other branches

7How · Step 3: Multi-Hop Traversal (Q1)

Start at "Yunshu", walk the edges

[GraphRAG] traverse from ['Yunshu Intelligence']: hop1: Yunshu --HAS_CEO--> Li Ming hop2: Li Ming --GRADUATED_FROM--> Weiming Inst. hop3: Weiming Inst. --LOCATED_IN--> Jiangcheng [generate] Answer: Yunshu's CEO is Li Ming, who graduated from Weiming Institute, located in Jiangcheng.

The whole chain is walked precisely — no reliance on similarity

7Contrast · Q2 Aggregate Traversal (expand + filter)

hop1: Xinghuan --HAS_SUBSIDIARY--> Yunshu / Hengxing / Guangnian hop2: Yunshu→Li Ming Hengxing→Wang Fang Guangnian→Chen Wei hop3: Li Ming→Weiming Wang Fang→Mingde Chen Wei→Beishan hop4: Weiming→Jiangcheng Mingde→Songdao Beishan→Yungang ⇒ filter "city = Jiangcheng" ⇒ Li Ming ✓

The essence: the hops traditional RAG misses are explicit edges in GraphRAG. Traversal walks edges, independent of "similarity", so the chain never breaks — that's the root reason it does multi-hop.

Traverse + filter by city ⇒ Li Ming

8Boundaries & Trade-offs

GraphRAG is not a silver bullet — it has costs.

DimensionTraditional RAGGraphRAG
Indexing costlow (embedding only)high (LLM triple extraction)
Best atsingle-hop, fact lookup, semantic searchmulti-hop, aggregation, relational reasoning
Depends onembedding qualityextraction quality + relation design
Explainabilityweakstrong (explicit path)

💡 In practice they are often combined: vector retrieval for coarse recall, graph structure for relational reasoning. This demo keeps them separate to sharpen the contrast.

TAKEAWAYS

In One Sentence

Traditional RAG retrieves by flat similarity matching, so cross-document multi-hop chains break;
GraphRAG makes the clues explicit as an entity-relation graph, turning retrieval into walking paths along edges,
which enables multi-hop reasoning and aggregate queries — and every step is visible & explainable.
